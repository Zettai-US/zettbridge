# Rust OOT kernel boundary / unsafe audit

Target: the exact `~/linux` tree recorded in deployment.json. The module links the target kernel's Rust metadata through Kbuild; no kernel source change is required. C helpers bridge missing inline/macro bindings, private DAX bus descriptors, AER/PM hooks and sysfs declarations. C has no device context, file operations, worker, backing allocation or lifecycle policy.

* `device.rs` implements native `pci::Driver` and `MiscDevice`, with `Arc<Core>`, a Rust `Mutex<KVBox<State>>`, `DelayedWork<Core>` and `Completion`. `ffi::PciAdapter` delegates registration/data layout to native `pci::Adapter<Bridge>` after installing AER/PM hooks. Every State entry (open/close, ioctl, sysfs, fault, DAX and work) holds the same sleepable mutex.
* State is allocated in place with Rust KVBox, never on the kernel stack. Zero initialization is valid because every field is an integer, boolean, array, aggregate of these, or nullable raw pointer. Its raw self-reference only points to the stable Arc allocation containing that State mutex. No pointer escapes to userspace. `unsafe impl Send for State` relies on this serialization and the absence of thread affinity.
* Native `MiscDeviceOptions` in this kernel does not expose owner, mode or parent. The Rust Node adapter uses its native generated vtable and a module-static immutable copy with `owner=THIS_MODULE`, plus mode 0600 and the PCI parent. Static fops storage remains valid after the Node is deregistered while old FDs survive. The callback's transparent `MiscDeviceRegistration<Session>` borrow overlays the identical pinned miscdevice layout; open recovers Node solely to clone its already initialized Arc. `misc_open` excludes deregistration during open. Each file owns a KBox<Session>; `vm_file` retains it through fork/VMA close. Native compat_ptr_ioctl handles the fixed-width ABI.
* User access uses Rust UserSlice typed reads/writes with audited `FromBytes` / `AsBytes` implementations. Both repr(C) records have no padding and only integer/byte fields; size/offset assertions and 32/64-bit C checks cover the ABI. Input is copied once before acquiring the State mutex; output is copied after releasing it. An EFAULT on copyout never rolls back an already recorded transaction.
* `backing.rs` owns a Rust page vector, SG table, PCI device reference and native CoherentAllocation. Page allocation enforces the requested NUMA node and verifies actual node/source. Physical addresses are used only for resource provenance; every extent address originates from a successfully mapped DMA SG entry. No userspace pins, raw DAX backing, SVA or SWIOTLB bounce mapping is accepted.
* A Backing destructor is available for construction failure and explicit release only. Published ownership is transferred from KBox into the unique, non-Copy OwnedBacking handle, which intentionally has no Drop. Rust lifecycle transitions invoke free only before publication or after positive drain+retire. The destructor drops the coherent table, unmaps DMA, frees SG metadata, then lets the Rust page vector release pages. Quarantine never relies on devres to preserve backing.
* SG allocation explicitly caps each input segment at 2 MiB. Mapped entries are copied once using the native Rust SGTable iterator into a Rust vector, avoiding quadratic descriptor lookup for large pools; bounce checks traverse original entries. Mapping/sync/unmap use the original table. Prepare fills every CPU byte, maps the pages, fills all coherent descriptors, requests TEST_DMA, then syncs/validates/zeroes payload only after a positive ACK. Device ownership resumes before commit; active provider code does not touch payload. The coherent table allocation's temporary bound-device view is justified by holding the online State mutex: PCI unbind must obtain the same mutex before revocation. No bound reference escapes.
* MMIO uses the Rust PCI Bar / Io API through short Devres revocable guards; no RCU guard spans a sleep. Split 64-bit accesses and dma_wmb match the ABI. ACK epoch/status is protected by a repeated ACK sequence read. Polling and independent query retries are bounded; uncertainty cannot be erased by a later command.
* Fault lock order is MM's VMA lock → State mutex. The worker first marks leases RELEASING/frozen under State, drops the mutex before unmap_mapping_range and synchronous TLB invalidation, then reacquires it before the hardware barrier. UC PFNs are inserted only for ACTIVE leases. Released/faulted accesses return SIGBUS. An inode reference retains one shared address_space for every open, including alternate device-node inodes, so revoke covers all mappings. Four GiB per handle separates identity from offsets introduced by VMA splitting; allocations exceeding that per-lease span fail with E2BIG before changing the ledger, while multiple leases can cover a larger pool. VM_MAYEXEC is cleared.
* DAX probe uses the role registry to clone the consumer Arc, matches HPA/size to the exact linked Type 3 HDM decoder, takes exclusive request_mem_region ownership, then pins the module. No generic /dev/dax mapping is registered. DAX removal freezes/revokes and retains both its claim and Arc; it is not a retirement proof.
* Active owns the running worker before callbacks become discoverable, including probe failure paths. PCI unbind freezes State and sets online=false, waits for the last worker to acknowledge shutdown, then flush_work waits for its final callback/Arc destructor to return. Mapping revocation runs without the State mutex. Native devres may then revoke BAR access while old FDs retain Core and return ENODEV. Empty devices can release their PCI/inode/State references and unload normally.
* Backing ownership or DAX attachment pins the module separately from file references. Active teardown retains a QuarantineOwner Arc whenever resources remain; the role registry stays occupied to reject a fresh epoch-zero instance over uncertain hardware. Pages, DMA mappings, inode/device references and exclusive DAX claims survive independently of PCI devres. There is no administrative quarantine-release operation in this profile. Even normal consumer detach keeps DAX ownership until guest teardown.
* `ffi.rs` raw callbacks are supplied live kernel-owned pointers with documented registration lifetimes. `backing.rs` additionally contains the audited page/SG pointer boundary; ownership and bounds checks are in Rust. The extern-block improper_ctypes allowance is limited to pointers into generated C types containing configuration-dependent empty lockdep structs; those structs never cross FFI by value.

This baseline uses unbound delayed work, not MSI-X. QEMU's synchronous DMA completion is functional evidence only; physical AER/PM/reset behavior, posted writes and cache maintenance require separate platform qualification. See validation.md for executed tests and limits.

ATS extension: `ffi::check_ats` reads PCI configuration through kernel bindings during probe and verifies the IOMMU-owned ATS enable state. The driver never independently toggles ATS, so Intel IOMMU's device-TLB bookkeeping stays authoritative. The temporary bound-device borrow for ATS test buffers follows the same online State mutex rule as the extent table. A successfully acknowledged test buffer is freed through native CoherentAllocation; an uncertain completion transfers it into `Backing::ats_probe`, retained together with the quarantined backing. Read-only sysfs ATS counters use cached State fields and add no MMIO to show callbacks. The hardware/model's RETIRE ACK now also proves its ATC is empty before Rust unmaps backing; ATS remains enabled through the DMA API unmap operations.
